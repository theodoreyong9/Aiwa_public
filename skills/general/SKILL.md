# The way to work

- A file you create is a creation. Look for references, find an idea, and push the result further than the obvious first version.
  Catalogues, kits and templates are raw material, never a replacement for the idea.
- Write in the language of the request. Facts (names, dates, amounts) come from the request or from the repository; what is missing, you
  assume reasonably and say so in one sentence.
- Small steps that work beat a large step that might: build, run, look at the result, then go on.
- Leave the repository cleaner than you found it: no dead file, no commented-out code, no secret anywhere.
- When the request is not one of the kinds of file (a refactor, a fix, a question about the code), do it in the code of the repository,
  with its tests, and integrate it into the default branch when it is green.
- The kit of Aiwa (free music, footage, 3D assets, measured design references, the video tools) is in
  https://github.com/theodoreyong9/Aiwa_public/tree/main/skills/kit : each tool has a README that says what it does and how to call it.
